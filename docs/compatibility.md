# Current limits and remaining work

The user successfully built and installed the player and reports two independently imported games working on an iPhone. Logs under `Errors/` confirm Godot 4.7.2 ARM64 execution on an A17 Pro. The new mouse bridge, draggable/remappable controls, and native-extension fallback are source changes awaiting CI compilation and device testing.

The first adapter targets complete, unencrypted Godot 4 GDScript packs. Header metadata suggests a candidate runtime; it cannot prove rendering, bytecode, assets, API, autoload, or scene compatibility. A 4.7.2 runtime may fail older 4.x exports despite accepting their headers. Versions newer than 4.7 are rejected. Godot 3 is detected but cannot launch. The manual override selects among known adapters and never overrides an unsupported engine major.

The inspector supports pack-directory formats 1–4, separates format and engine versions, validates bounded directory reads, paths, offsets, settings signatures and resource bounds, and rejects encrypted/sparse/delta/removal archives and .NET source. Native descriptors/libraries produce a warning and require the explicit “Try without native extensions” option before Play. Native loading remains blocked at the engine boundary. Optional extensions may be unused during offline play; required native classes can still prevent startup. Asset payload checksums and dependency completeness are not exhaustively checked. Encrypted scripts, external resource bundles, Windows native APIs, C#, GDNative and executable GDExtensions remain unsupported.

Metal and OpenGL ES are compiled. The supplied logs show both Compatibility and Mobile renderers working on iPhone. Explicit Vulkan-only settings, platform-specific textures, unsupported codecs, plugins, and desktop shader assumptions may require a compatible game export; there is no automatic asset conversion.

The official Godot controller/keyboard/touch paths are retained. Virtual buttons emit key press/release events, including modifiers and physical key codes. Source now includes a per-game layout editor, arbitrary keyboard mappings, mouse-button mappings, saved visibility, and a visible mouse overlay with trackpad/direct modes, clicks, dragging and scrolling. Mouse APIs are implemented in the Apple display server to address the supplied unsupported-mouse errors. Captured/hidden cursor modes and custom cursor images are honored; built-in cursor shapes currently share the default arrow. The new features, audio focus, rotation and safe areas need device testing. Virtual gamepad buttons, scaling overrides, diagnostics toggles and FPS UI remain unimplemented.

Pokémon Battle Advanced 0.3.3 includes a native WebRTC descriptor with no iOS library. Its scripts initialize the connection backend only when using host/join. The original pack reaches its boot scene on Windows 4.7.2 without that backend and without script parse errors. Full gameplay and iPhone startup remain unverified; online WebRTC will not work in this build.

Per-game `user://` isolation is implemented for ordinary save APIs, including games with identical project names. It has not been device-tested. It is **not a security boundary between imported scripts**: ordinary GDScript can access other app-sandbox files by absolute path and can use network APIs when connectivity exists. iOS provides the app sandbox; this project does not implement a separate script sandbox. Import trusted games only. No online service is required to play.

There is one engine lifetime per process. After a launch attempt or engine setup failure, close and reopen the app. Returning to a running library, launching another engine in-process, crash recovery, and reliable engine teardown need further investigation. Logs created after Godot's file logger starts are in the UUID save directory; earlier initialization failures may only appear in the Xcode/device console.

## Godot 3 adapter plan

`PlayerRuntime` is the Objective-C runtime boundary and `RuntimeSelection` is the selection gate. Only the Godot 4 implementation is present. Godot 3.6.3 has not been linked, compiled, or executed in this app.

Adding 3.6.3 requires inspecting its older iOS bootstrap and GLES renderer and implementing the same pre-project pack selection and UUID save path. The standard 3/4 static archives cannot coexist directly: they export overlapping C++ names, C entry points, Objective-C classes and process-global engine state.

Investigate separately built, pre-signed bundled framework images, hidden/localized symbols and version-prefixed Objective-C classes/entry points, with a versioned adapter ABI. Mach-O two-level namespaces alone do not isolate Objective-C class registration or every global dependency. Both framework images must be built and signed with the IPA; no imported executable code is permitted. Loading/unloading or restarting either runtime must be proven before promising switching. If sufficient isolation cannot be demonstrated, source-level symbol/class namespacing and additional engine patches are compile blockers, not solved features.
